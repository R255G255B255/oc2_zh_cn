# 中级 API
中级 API（MLAPI）提供了一种便于低级程序使用的设备交互方式。它主要供运行在[Z80处理器](item/cpu_z80.md)上的程序使用；[RISC-V电脑](item/cpu_riscv.md)也可以使用，详见下文。它通常提供一部分可通过[高级 API](hlapi.md)（HLAPI）访问的设备，并以便于 8 位机器使用的形式呈现：通过编号选择函数，参数和返回值都是普通字节。

各设备提供的函数代码请参阅[设备列表](device/index.md)。

这里的所有操作都通过端口完成，因此可以在汇编程序中使用。启动盘上的两个库可以帮你省去繁琐的部分：`DEVLIB.INC` 用于查找通用设备，`OCAPI.INC` 用于查找和调用中级 API 设备。请在源文件末尾包含它们：

```
INCLUDE DEVLIB.INC
INCLUDE OCAPI.INC
```

## 查找设备
设备可通过固定端口上的枚举窗口查找。`DEVS.COM` 会打印其中的内容，可用来初步确认设备是否已连接。

所有 MLAPI 设备都通过同一个端口响应，并通过 MLAPI 设备索引彼此区分。`OCAPI.INC` 中的 `OCFIND` 可以按设备名称、设备类型或总线接口标签查找设备：
- `HL` 指向名称列表，每个名称都以零结尾，列表末尾还有一个额外的零表示结束。设备必须匹配所有名称，例如同时匹配标签和设备名称：`db 'storage',0,'ITEMS',0,0`
- `B` 指定要查找第几个匹配设备；存在多个匹配项时，从零开始计数。
- 成功时，进位标志清零，`A` 保存通信端口，`E` 保存 MLAPI 设备索引。
- 失败时，进位标志置位。

将 `E` 写入 `OCSEL` 寄存器以选择设备，然后使用 `A` 中的端口进行操作。除非选择其他设备，否则当前选择会一直有效。总线上的设备发生变化后，请重新读取索引，因为索引可能会改变。

每台电脑和机器人都有一个 [`SYSTEM`](device/system.md) 设备。其他设备使用编号来标识物品、流体和方块，以节省总线带宽。可以通过 `SYSTEM` 设备查询编号对应的名称，反之亦然。它的 MLAPI 设备索引始终为 0，因此无需先调用 `OCFIND` 就能使用。

## 发起调用
`OCFIND` 返回的端口有四个寄存器，在 `OCAPI.INC` 中命名如下：
- `OCSEL` 用于选择 MLAPI 设备。
- `OCFUN` 接收函数代码并开始一次调用。
- `OCDAT` 接收参数字节，并返回结果字节。
- `OCSTA` 报告状态；写入 `OCEXEC` 可执行调用，写入 `OCABRT` 可放弃调用。

一次调用的流程如下：将函数代码写入 `OCFUN`，将每个参数字节写入 `OCDAT`，再将 `OCEXEC` 写入 `OCSTA`。随后轮询 `OCSTA`，直到 `OCBUSY` 清零；当 `OCDAV` 置位时，从 `OCDAT` 读取结果字节。

许多调用可能需要一段时间才能完成，因此务必轮询状态，不要直接继续执行。一次只能运行一个调用；`OCBUSY` 置位期间，只接受对 `OCSTA` 的写入。

如果状态中的 `OCERR` 置位，表示调用失败，`OCDAT` 会给出原因：
- `OCENOD`：不存在此 MLAPI 设备。
- `OCENOF`：不存在此函数。
- `OCEARG`：参数不符合该函数的要求。
- `OCEINT`：设备内部发生故障。

这些寄存器只保存一个设备选择和一次调用，因此请一次只进行一个调用，也不要在中断处理程序中发起调用。

## 等待事件
某些设备会主动报告状态变化，例如[红石接口](block/redstone_interface.md)接收到的信号发生变化时。通常，[设备列表](device/index.md)中的设备文档会列出该设备的事件。

以下寄存器用于处理事件：
- `OCEVC` 用于启用事件：写入 `OCEVQ` 可将事件加入队列，再加上 `OCEVI` 可同时启用中断。
- `OCEVD` 每次读取返回一个字节，依次为 MLAPI 设备索引、事件代码和一个两字节的值；返回的是队列中最早的事件。

有事件等待处理时，`OCEVC` 中的 `OCEVP` 位会置位。队列已满时到达的事件会丢失，每次发生这种情况时，`OCEVO` 位都会置位。

在 Z80 上启用中断后，`HALT` 会休眠，直到下一个事件到达，再由中断处理程序读取事件。启动盘上的 `REDWAIT.Z80` 就是这样工作的：它等待红石信号变化，然后打印侧面和新的信号强度。编译方法与下文的 `REDSTN.Z80` 相同。

## 示例
启动盘上的 `REDSTN.Z80` 用于控制[红石接口](block/redstone_interface.md)，源码注释中也包含对应的 C 代码，便于阅读。如果要写入软盘，则需要[磁盘驱动器](block/disk_drive.md)。请留在 `A:` 盘上进行编译：

```
ZMAC REDSTN /OB:REDSTN /E
ZML B:REDSTN
```

第一个命令汇编源文件。`/O` 会将结果放到 `B:REDSTN.REL`，`/E` 会关闭错误日志。第二个命令将其链接为 CP/M 可运行的 `B:REDSTN.COM`：

`B:REDSTN 1 15`

这会将侧面 1（上方）的输出设为 15。在电脑上方放置一个红石灯，它就会亮起。省略信号强度参数即可读取信号强度：

`B:REDSTN 1`

要编写自己的程序，可以使用启动盘上的 `ED` 创建和编辑源文件，例如 `ED B:PROG.Z80`。

## 在 RISC-V 电脑上使用
Linux 将相同的寄存器提供为文件 `/dev/uio0` 中的一个内存页。打开该文件需要 `root` 权限。C 头文件 `mlapi.h` 提供了查找和映射此内存区域的工具；映射后的布局与上文相同。它还提供了按名称查找设备的辅助函数 `mlapi_find(0, "storage", "ITEMS")`，其匹配规则与 `OCFIND` 相同，并提供发起调用的功能。该头文件位于 `/mnt/builtin/include`，`tcc` 应能自动找到它。

`/mnt/builtin/example/redstone.c` 在 Z80 上实现的功能与 `REDSTN.Z80` 相同。可直接运行：

`tcc -run /mnt/builtin/example/redstone.c 1 15`

不带参数运行时，它会像 `REDWAIT.Z80` 一样工作：`mlapi.h` 中的 `mlapi_events_wait` 会休眠，直到下一个事件到达。

`/mnt/builtin/example/devices.c` 会列出每个设备的索引和名称：

`tcc -run /mnt/builtin/example/devices.c`

整台电脑只有一个设备选择和一个调用状态。一次只能让一个程序使用这个内存页。
