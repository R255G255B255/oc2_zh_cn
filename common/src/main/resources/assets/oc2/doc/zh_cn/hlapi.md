# 高级 API
使用 Lua 控制设备是[电脑](block/computer.md)的核心功能之一。许多设备都属于高级 API（HLAPI）设备。这意味着它们不是通过常规 Linux 驱动程序控制，而是通过简单的 RPC 系统控制：在串行设备上收发 JSON 消息。

本文中的所有内容都需要[RISC-V处理器](item/cpu_riscv.md)附带的 Linux 系统。若要通过[Z80处理器](item/cpu_z80.md)访问设备，请参阅[中级 API](mlapi.md)（MLAPI）条目。

如果连接了多个相同类型的设备，`find` 可能会返回其中任意一个。若要指定某个设备，可以用[扳手](item/wrench.md)为目标设备前方的总线接口设置名称，然后按该名称查找。可以传入多个名称：`find("storage", "item_handler")` 只会匹配同时具有这两个名称的设备。

设备提供的方法请参阅[设备列表](device/index.md)。

## 设备库
默认的 Linux 发行版包含一些库，可让 HLAPI 设备更易于使用。`devices` 库提供发现设备、调用设备方法，以及在可用时获取设备文档的实用工具。

注意：本文使用 Lua 介绍概念、示例和 API 文档。Micropython 也提供了功能相同的库。

使用 `require("devices")` 导入 `devices` 库。返回值是一个对象，因此调用其方法时要使用冒号表示法：将它存入变量后，调用 `d:list()`，而不是 `d.list()`。

### 方法
`list():table` 返回当前所有可用设备的列表。返回表中的每个条目都代表一个设备，包含其类型名称和唯一标识符。
- 返回已连接的 HLAPI 设备列表。

`get(id:string):Device` 返回指定标识符设备的包装对象。这与 `find` 类似，但这里传入的是特定标识符，而不是类型名称。
- `id` 是设备的唯一标识符。
- 返回指定设备的包装对象；如果没有设备具有该标识符，则不返回任何内容。

`find(typeName:string...):Device` 返回具有所有指定名称的设备的包装对象。名称可以是设备类型、设备名称以及在[总线接口](block/bus_interface.md)上设置的别名。如果存在多个匹配设备，返回哪一个是不确定的。
- `typeName` 是设备必须具有的一个或多个名称。
- 返回匹配设备的包装对象；如果没有设备具有所有指定名称，则不返回任何内容。

`methods(id:string):table` 返回指定标识符设备所提供的方法列表。若要以更易读的方式查看方法列表，可以获取设备包装对象并将其转换为字符串。另请参阅“设备包装对象类型”一节。
- `id` 是设备的唯一标识符。
- 返回设备提供的方法列表。
- 如果获取方法列表失败，则抛出错误。

`invoke(id:string, methodName:string, ...):any` 调用指定标识符设备上具有指定名称的方法，并传入额外参数。不建议直接使用此方法；更推荐获取设备包装对象后，通过它调用方法。另请参阅“设备包装对象类型”一节。
- `id` 是设备的唯一标识符。
- `methodName` 是要调用的方法名称。
- `...` 是要传给该方法的参数。
- 返回该方法的结果。
- 如果调用失败或方法抛出异常，则抛出错误。

`waitEvent(timeout:number, eventType:string):table` 等待设备发送下一个事件，例如[机器人](robotics.md)完成动作时发送的事件。
- `timeout` 是等待时长，单位为毫秒。传入 `nil` 表示无限期等待。
- `eventType` 是可选的事件名称。指定后，等待期间会丢弃其他类型的事件。
- 返回事件表，包含 `type` 和 `data` 条目；如果事件由设备发送，还会包含 `deviceId`。如果等待超时，则不返回任何内容。事件和方法结果是分开传递的，因此触发方法调用的事件可能会先于该调用的结果到达。

`blob(data:string):Blob` 将二进制数据封装起来，以便作为参数传给设备方法。其他参数都会以文本形式发送，非文本数据会因此损坏。
- `data` 是要封装的字节。
- 返回可作为参数传递的值，例如 `device:writeExportFile(d:blob(bytes))`。

## 设备包装对象
从 `devices` 库获取的设备是 `Device` 类型的对象，它是一个保存设备标识符的包装对象。

它主要用于无缝调用设备提供的方法，并在可用时便捷地查看设备文档。

要调用包装对象上的方法，请使用冒号表示法和方法名称。例如：

`wrapper:someMethod(1, 2, 3)`

`wrapper:waitEvent(timeout:number, eventType:string)` 的用法与库上的 `waitEvent` 相同，但只返回此设备发送的事件。等待期间会丢弃其他设备发送的事件。

要查看设备文档，将包装对象转换为字符串即可。在 Lua 解释器中输入 `=wrapper`。

## 同时运行多个脚本
RPC 系统使用的串行设备一次只能由一个程序打开。名为 `oc2busd` 的小型后台服务会在电脑启动时打开这些设备，并为其他程序中转消息。服务运行时，任意数量的脚本都可以同时使用 `devices` 库。

调用仍会按照到达顺序逐个执行，因此两个脚本即使控制同一设备，也不会在操作中途交错执行。

事件（例如[机器人](robotics.md)完成动作时发送的事件）会发送给*所有*正在监听的脚本。因此，在某个动作执行到一半时才启动的脚本，也可能收到它并未发起的动作事件；请检查事件是否对应你正在等待的动作。`waitEvent` 可以接收事件名称，用于提前筛选事件。

每次调用 `require("devices")` 都会为脚本建立一个到服务的连接。若要同时保持多个连接（例如避免长时间运行的调用阻塞其他操作），可以显式打开额外连接：

`bus = require("oc2.bus").connect()`

不再需要时，使用 `bus:close()` 关闭此类连接。最好不要关闭 `require("devices")` 建立的连接，因为脚本中的其他代码也会共用它。

如果服务没有运行，`devices` 库会退回到直接打开串行设备。功能仍然可用，但同一时间只能由一个程序使用。服务会将信息写入系统日志；运行 `cat /var/log/messages` 可以查看它停止的原因。

## 示例
本例将控制一个[红石接口方块](block/redstone_interface.md)。首先放置该方块，并使用[总线线缆](block/bus_cable.md)和[总线接口](block/bus_interface.md)将它连接到电脑。

![红石接口设置](../img/scripting_redstone_interface.png)

我们在红石接口上方放置一个红石灯，以便直观确认命令是否生效。

要确认设备与电脑之间的连接，请在命令行运行 `lsdev.lua`。它会列出所有已连接 HLAPI 设备的标识符和类型名称。其中一个设备的类型名称应包含 `redstone`。

在命令行中只运行 `lua`，即可启动 Lua 交互模式。

![Lua 交互模式](../img/scripting_lua_interactive.png)

导入设备库，并将它存入名为 `d` 的变量：

`d = require("devices")`

然后获取红石接口方块的 `Device` 包装对象，并将它存入名为 `r` 的变量：

`r = d:find("redstone")`

这里传给调用的 `redstone` 是设备类型名称，正是刚才通过 `lsdev.lua` 确认的名称。

现在我们有了红石接口方块的包装对象，可以在其上调用方法。要查看可用方法列表，请运行 `=r`。

本例要使用的是 `setRedstoneOutput` 方法。它可以设置红石接口发出的信号。

要点亮红石灯，我们需要让红石接口方块的顶面输出红石信号：

`r:setRedstoneOutput("up", 15)`

现在红石灯应该亮起来了！

![点亮的红石灯](../img/scripting_lamp.png)

至此，你已经掌握了如何查看已连接设备的名称、设备提供的方法，以及如何获取设备文档。接下来可以尝试红石接口的其他方法来读取输入信号，或试试其他设备！
