# 基本
本文档包含有关 [电脑](block/computer.md) 如何工作的一些基本信息。 这并不一定意味着这些信息很容易阅读。 这里的基本是指所使用的一般概念。

## 架构
电脑需要CPU运行，可选CPU有 [Z80](item/cpu_z80.md) 和 [RISC-V](item/cpu_riscv.md)。详细信息请查看各自文档，Z80可以运行CP/M并通过[MLAPI](mlapi.md)连接设备，RISC-V可以运行Linux并通过[HLAPI]连接设备。

### 原生设备
连接到RISC-V的原生设备是内存映射设备。 在Z80上是端口映射设备，这意味着它们被映射到物理内存中的某个区域或专用设备端口。 电脑使用常规的 Linux 驱动程序或自带的BIOS与之交互。Z80仅限磁盘驱动器。

电脑上运行的软件会通过 RISC-V 上的扁平设备树、Z80 上的枚举窗口获知有哪些设备可用，以及这些设备位于何处。该设备树可能包含有关系统整体的一些附加信息。特别是，它还存储已安装内存的大小。由于此数据结构在启动期间会被复制，因此之后无法更新。这就是当原生设备（例如网络接口卡）发生更改时，必须重新启动电脑的原因。适用这种情况的设备通常会在其工具提示中带有相应说明。

### HLAPI 与 MLAPI 设备
其它类型设备是高级和中级 API 设备，有时也称为 RPC 或 IO 设备。这些设备使用单个控制器，通过单个串行设备与[电脑](block/computer.md)通信。该控制器设备存在于所有电脑中，负责从多个设备收集消息，并将消息分发给设备。该控制器使用的协议分别是简单的基于 JSON 消息的协议和基于寄存器的二进制协议。默认 Linux 库提供的 `devices` Lua 库封装了用于连接该控制器的串行设备。默认 CP/M 镜像附带的 `DEVLIB.INC` 和 `OCAPI.INC` 库可简化对枚举窗口的访问。因此，在使用 HLAPI/MLAPI 设备（例如[红石接口方块](block/redstone_interface.md)）时，*强烈*建议使用这些库。

由于所采用协议的性质，数据传输速率相当有限。因此，大多数设备通常只提供相对简单的 API，这些 API 不需要在任一方向上发送大量数据。

## 配置
电脑可以在一定程度上进行配置。内存容量、以[硬盘](item/hard_drive.md)形式提供的额外存储，以及最重要的——安装哪些扩展卡，在很大程度上由用户决定。请注意，默认 Linux 发行版至少需要 8M 内存，建议使用 10M。CP/M 只需要 64KB，因此任何内存模块都可以。

大多数组件都会增加电脑的整体能耗。为节约能源，只选择必要的组件至关重要。

## Linux
默认 Linux 发行版包含一些基本命令行工具，以及编写和运行 Lua 程序的能力。有关如何使用 Lua 与 [HLAPI](hlapi.md) 设备交互的概述，请参阅该手册条目。

原生设备使用常规 Linux 驱动程序。例如，硬盘会显示为 `/dev/vdaX` 设备，可以按常规方式格式化和挂载。

电脑提供两个硬件时钟（RTC）设备。第一个以大多数用户习惯的时间尺度计时。默认使用它，例如 `date` 和 `time` 等命令行工具。第二个按照电脑所在世界中的时间流逝方式计时。要获取当前世界时间，请使用 `hwclock -f /dev/rtc1`。

## CP/M
默认 CP/M 发行版包含一些基本命令行工具，以及编写、汇编、链接和运行汇编程序的能力。有关如何使用汇编与 [MLAPI](mlapi.md) 设备交互的概述，请参阅该手册条目。

磁盘驱动器使用常规 BIOS。例如，额外的软盘驱动器会显示为带盘符的驱动器，如 `B:`。
