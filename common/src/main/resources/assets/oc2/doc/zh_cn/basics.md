# 基本
本文档介绍 [计算机](block/computer.md) 工作方式的一些基础知识。这里的“基础”指的是所涉及的一般概念，并不意味着内容简单。

## 架构
计算机需要 CPU 才能运行，可选的 CPU 有 [Z80](item/cpu_z80.md) 和 [RISC-V](item/cpu_riscv.md)。详细信息请查看各自文档：Z80 可以运行 CP/M 并通过 [MLAPI](mlapi.md) 连接设备，RISC-V 可以运行 Linux 并通过 [HLAPI](hlapi.md) 连接设备。

### 原生设备
连接到 RISC-V 的原生设备是内存映射设备，在 Z80 上则是端口映射设备，也就是映射到物理内存中的某个区域或专用设备端口。计算机通过常规 Linux 驱动程序或自带的 BIOS 与它们交互；Z80 仅支持磁盘驱动器。

计算机上运行的软件会通过 RISC-V 上的扁平设备树或 Z80 上的枚举窗口，获知可用设备及其位置。设备树还可能包含系统的其他信息，尤其是已安装内存的大小。由于该数据结构会在启动期间复制，之后无法更新。因此，原生设备（例如网络接口卡）发生更改时必须重新启动计算机；需要这样操作的设备通常会在工具提示中注明。

### HLAPI 与 MLAPI 设备
其它类型设备是高级和中级 API 设备，有时也称为 RPC 或 IO 设备。这些设备通过单个串行设备与[计算机](block/computer.md)中的控制器通信。该控制器存在于所有计算机中，负责收集并分发来自多个设备的消息。它使用的协议分别是基于 JSON 消息的简单协议和基于寄存器的二进制协议。默认 Linux 系统提供的 `devices` Lua 库封装了用于连接该控制器的串行设备。默认 CP/M 镜像附带的 `DEVLIB.INC` 和 `OCAPI.INC` 库可简化对枚举窗口的访问。因此，使用 HLAPI/MLAPI 设备（例如[红石接口方块](block/redstone_interface.md)）时，*强烈*建议使用这些库。

由于所采用协议的性质，数据传输速率相当有限。因此，大多数设备通常只提供相对简单的 API，这些 API 不需要在任一方向上发送大量数据。

## 配置
计算机可以在一定程度上进行配置。内存容量、以[硬盘](item/hard_drive.md)形式提供的额外存储，以及最重要的扩展卡选择，在很大程度上由用户决定。请注意，默认 Linux 发行版至少需要 8M 内存，建议使用 10M。CP/M 只需要 64KB，因此任何内存模块都可以。

大多数组件都会增加计算机的整体能耗。为节约能源，只选择必要的组件至关重要。

## Linux
默认 Linux 发行版包含一些基本命令行工具，以及编写和运行 Lua 程序的能力。有关如何使用 Lua 与 [HLAPI](hlapi.md) 设备交互的概述，请参阅该手册条目。

原生设备使用常规 Linux 驱动程序。例如，硬盘会显示为 `/dev/vdaX` 设备，可以按常规方式格式化和挂载。

计算机提供两个硬件时钟（RTC）设备。第一个按大多数用户熟悉的时间尺度计时，并由 `date`、`time` 等命令行工具默认使用。第二个按照计算机所在世界中的时间流逝方式计时。要获取当前世界时间，请使用 `hwclock -f /dev/rtc1`。

## CP/M
默认 CP/M 发行版包含一些基本命令行工具，以及编写、汇编、链接和运行汇编程序的能力。有关如何使用汇编与 [MLAPI](mlapi.md) 设备交互的概述，请参阅该手册条目。

磁盘驱动器使用常规 BIOS。例如，额外的软盘驱动器会显示为带盘符的驱动器，如 `B:`。
